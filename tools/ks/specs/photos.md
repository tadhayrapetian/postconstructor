# Module `photos` — «Фото»: поиск фото, Pinterest, «Мои фото»
Rail tab: group `photo`, title «Фото», before `prep`, `screen:true` (results/library grid on the big screen; side panel = search box, sources, filters, drop zone, settings).

The user explicitly asked "как подключить поиск фото Pinterest внутри программы". Pinterest has no public search API and forbids framing, so the module must give the best real alternative:
1. **Search in free photo stocks** directly inside the app:
   - Without any key: **Openverse** (`https://api.openverse.org/v1/images/?q=…&page=N&page_size=30&license_type=commercial&mature=false`, fields `results[].{id,title,url,thumbnail,width,height,creator,license,license_version,license_url,foreign_landing_url,source}`) and **Wikimedia Commons** (`https://commons.wikimedia.org/w/api.php?action=query&format=json&origin=*&generator=search&gsrnamespace=6&gsrsearch=…&gsrlimit=30&gsroffset=…&prop=imageinfo&iiprop=url|size|mime|extmetadata&iiurlwidth=480`; skip non-image mimes; author/license from extmetadata Artist/LicenseShortName, strip HTML).
   - With a free personal key entered in «Ключи фотобанков» (stored in `KS.store('photos').keys`): **Pexels** (`https://api.pexels.com/v1/search?query=…&per_page=30&page=N&orientation=&color=`, header `Authorization: <key>`; `photos[].{id,width,height,url,photographer,photographer_url,alt,avg_color,src.{original,large2x,large,medium}}`), **Unsplash** (`https://api.unsplash.com/search/photos?query=…&per_page=30&page=N&orientation=&color=&client_id=<key>`; `results[].{id,width,height,color,alt_description,urls.{full,regular,small},user.{name,links.html},links.{html,download_location}}`; when a photo is USED you must GET `links.download_location` + `&client_id=` (API rule); attribution "Фото: <name> / Unsplash"), **Pixabay** (`https://pixabay.com/api/?key=<key>&q=…&per_page=30&page=N&image_type=photo&safesearch=true&orientation=&colors=`; `hits[].{id,webformatURL,largeImageURL,imageWidth,imageHeight,user,pageURL,tags}`).
   - Each key field has a link «Получить бесплатный ключ» (pexels.com/api, unsplash.com/developers, pixabay.com/api/docs) and a «Проверить» button.
   - Source chips: Все / Openverse / Wikimedia / Pexels / Unsplash / Pixabay (keyed sources disabled with a hint until a key is set). «Все» queries available sources in parallel and interleaves results.
   - Russian queries: stocks work best in English. Include a built-in RU→EN dictionary (≥ 300 common words for print-shop themes: цветы, свадьба, кофе, торт, дети, осень, море, горы, Ереван, Арарат, бизнес, офис, ресторан, пицца, суши, маникюр, салон, авто, спорт, йога, фитнес, медицина, зубы, праздник, новый год, шары, сердце, фон, текстура, мрамор, акварель, золото, дерево, бумага, узор, геометрия, небо, закат, лес, животные, кошка, собака…); translate word-by-word with phrase matches first; show «Ищем: flowers wedding» under the box; Armenian/English pass through. Plus quick theme chips (≈ 24) under the search box.
   - Filters: ориентация (любая/горизонт./вертик./квадрат), цвет (where the API supports it), «Только для коммерческого использования» (Openverse license_type; others are free for commercial use).
   - Result grid on the screen: lazy thumbnails, author line, source badge, size in px, and a print-quality badge computed for the CURRENT product: dpi = px / (product width mm / 25.4) → «300 dpi — отлично», «150–300 — нормально», «< 150 — только мелко». «Показать ещё» paging. Loading skeletons, empty/error states (offline, 401 bad key, 429 limit, CORS failure) with clear Russian messages.
   - Click a result → preview card (large image, author, license, link to source) with actions: **«В макет»** (KS.addImage auto), **«Заменить выбранное фото»**, **«Сделать фоном»**, **«Палитра из фото»** (KS.palette), **«В мои фото»**, «Открыть источник». Download the large version (≤ 3200 px) with KS.fetchImage; if CORS blocks it, try `<img crossOrigin="anonymous">`→canvas; if still blocked, explain and open the source page. Store `credit` on the element; show it in an inspector section (`KS.insp`) for img elements that have credit («Автор фото… Лицензия…», link).
2. **Pinterest**: button «Найти в Pinterest» opens `https://www.pinterest.com/search/pins/?q=<query>` in a new tab/window (on iPad works with Split View). A clear 2-line hint: «Перетащите понравившуюся картинку из Pinterest сюда или скопируйте её и нажмите ⌘V». The panel has a large drop zone (`.ks-drop`) that accepts: image files; `text/uri-list`/`text/plain` URLs; `text/html` with `<img src>` (Pinterest drags give this) — take the largest `i.pinimg.com` variant by rewriting `/236x/`, `/474x/`, `/736x/` → `/originals/` and fall back to 736x if originals fails. Fetch via KS.fetchImage → canvas fallback → if blocked: message «Pinterest не отдал картинку. Нажмите на неё правой кнопкой → «Скопировать изображение», потом ⌘V здесь». While the Фото tab is open, ⌘V/paste of an image or image URL anywhere (not in a text field) imports it. Also an input «Вставить ссылку на картинку». Imported pictures go to «Мои фото» (album «Разное») and show the same action card. Mention in the UI that Pinterest pictures belong to their authors (fine for ideas/palettes; for client print prefer stocks) — one short line, not a lecture.
3. **«Мои фото»** library (second sub-tab in the same group, `seg:'Мои фото'`, screen grid): IndexedDB per HOST.md convention (`ph:<id>` in store `files`; generate a ≤360px thumb on import). Multi-upload (file picker multiple, drag many files, paste), albums (Клиенты, Фоны, Логотипы, Документы, Разное + custom), rename, delete (with undo toast), search by name, sort by date, select several → «Общая палитра» (combine up to 6 photos into one palette via sampling and dzRoles/dzSetPalette). Storage meter (navigator.storage.estimate) and «Не удалять мои фото» (navigator.storage.persist). Same action card as search results. Listen to `photosChanged`.
4. Commands (⌘K): «Найти фото», «Мои фото», «Палитра из фото». Toolbar button (KS.tool) «Фото» that opens the tab.
Make it beautiful: clean masonry-like grid (CSS columns or grid with aspect boxes), smooth hover overlays with action icons on desktop, tap-to-open card on iPad.
Tests: mock every API (realistic JSON incl. errors 401/429) and image URLs (generate PNG bytes in node with `Access-Control-Allow-Origin: *`; and one image host WITHOUT CORS to test the fallback path); simulate drops with DataTransfer (files, uri-list, html with pinimg URL) and paste events; verify images land in the design and in IndexedDB, survive reload.
